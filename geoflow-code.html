01
The Problem · 为什么需要一门「语言」

上一代蛋白质生成模型的三道坎

/ 01

只能设计 Binder

如同一个只能「补全视频」的生成模型 —— 能产出一个结合靶点的分子,却无法自定义、无法做更精细的修改。

/ 02

亲和力不足,或不可成药

生成的分子结合力弱,或表达量低、非特异性高、稳定性差 —— 能结合,却难以走向成药。

/ 03

复杂需求无法设计

「结合 A 不结合 B」「只在特定微环境激活」—— 真实研发场景的复杂需求,难以转化为模型输入。

03
The Concept · 核心创新

把蛋白质设计,抽象成一门语言

生成、评估、优化 —— 这些曾经需要人工搭建的固定流程,如今被抽象为 GeoFlow Code 的基本算子。模型学会这门语言后,即可像积木一样自由组装,自主完成复杂设计任务。

geoflow_code — 基本算子(示意)
# 基本算子
generate()   # 围绕目标生成候选分子
evaluate()   # 结构、结合、成药性评估
optimize()   # 多目标迭代优化循环
select()     # 自主挑选实验分子

# 自由组装:随需调用,而非固定流程
pipeline = compose(
  generate(target="CLDN6"),
  evaluate(bind="CLDN6", avoid=["CLDN3","CLDN9"]),
  optimize(goals=["affinity","Tm","expression"]),
  select(top_k=20)
)

为什么是一门「语言」,而不只是又一个智能体

  • 更底层的元能力 —— 智能体只是使用这门语言的一种方式;语言本身更基础、更可组合
  • 打破固定流程 —— V3 是「设计-筛选-进化」的固定工作流,V4 让每个环节随需调用、自由组合
  • 生物学家友好 —— 无需编写代码,以自然语言描述意图即可获得专家级的模型调用能力
  • 穷尽探索空间 —— 不止是提速,更是让设计质量超越人工经验的边界

成药性评价

不只追求结合,默认通盘考量成药性

表达量、非特异性、热稳定性等指标被系统性纳入设计与评估 —— 输出的是「可直接进入后续研发」的分子,而非仅仅是「能结合靶点」的 Binder。成药性表现与业界现有抗体药产生方法处于同一优秀区间。
